# Optimal Cutting

A web application that computes and visualises the optimal cutting layout for wooden plates,
minimising material waste — and lets the user pick the packing strategy that matches the
machine actually doing the cutting.

**Backend:** Python 3 · FastAPI · Pydantic · rectpack
**Frontend:** React 18 · Vite · Tailwind CSS

---

## The problem

Cutting a set of ordered pieces out of standard-size plates is a variant of the
**2D bin packing / cutting stock problem**. Every square metre of offcut is money thrown away,
so the layout matters — but the *right* layout depends on the machine:

- A **panel saw** can only make **guillotine cuts** — every cut runs edge to edge, straight
  through the plate. Layouts that a router could handle are physically impossible here.
- A **CNC router** can cut any contour, so pieces can be **nested** freely for a tighter fill.

Because of that, this project does not hard-code a single algorithm. The packing strategy is a
parameter, and the optimiser is built so new machine types and strategies can be added without
touching the rest of the code.

## Architecture

```
frontend/          React + Vite UI
  src/api/         HTTP client for the optimiser
  src/components/  PieceInput · MachineSettings · CuttingVisualizer · ResultsPanel

backend/           FastAPI optimisation service
  app/main.py      HTTP layer — single POST /optimize endpoint
  app/schemas.py   Pydantic request/response contracts
  app/services/    OptimizerService — the packing and costing engine
```

The frontend holds no optimisation logic. It collects the piece list and machine
configuration, posts them to the API, and renders the returned layout.

## Packing strategies

Selectable per request via `config.algorithm`:

| Option      | rectpack strategy    | Best suited to                                        |
|-------------|----------------------|-------------------------------------------------------|
| `guillotine`| `GuillotineBssfSas`  | Panel saw — edge-to-edge cuts (default)               |
| `strips`    | `GuillotineBlsfLas`  | Panel saw, strip-oriented layouts                     |
| `nesting`   | `MaxRectsBl`         | CNC router — free nesting, tightest fill              |
| `simple`    | `SkylineBl`          | Fast approximation for quick estimates                |

## What the optimiser handles

- **Saw kerf compensation** — each piece is inflated by the blade width before packing, so the
  material consumed by the cut itself is accounted for rather than discovered on the shop floor.
- **Optional 90° rotation** — can be disabled for materials with a grain direction.
- **Identical-layout grouping** — plates that end up with the same layout are collapsed into one
  entry with a quantity. The operator sees *"cut this layout ×7"* instead of seven identical
  drawings.
- **Cutting-time estimate** — derived from machine parameters: cutting speed (m/min), handling
  time per cut, and plate loading time.
- **Input validation** — a piece that cannot fit the plate in any orientation is rejected with
  HTTP 400 and a message naming the offending piece, instead of silently producing a bad layout.

Returned metrics: total plates, material efficiency (%), total cuts, total waste, estimated time.

## API

### `POST /optimize`

Request — a furniture order cut from standard 2800 × 2070 mm plates:

```json
{
  "pieces": [
    { "id": "door",  "length": 716,  "width": 396, "quantity": 24 },
    { "id": "shelf", "length": 1200, "width": 500, "quantity": 10 },
    { "id": "side",  "length": 2000, "width": 600, "quantity": 8 }
  ],
  "config": {
    "sawWidth": 3,
    "plateLength": 2800,
    "plateWidth": 2070,
    "algorithm": "guillotine",
    "allowRotation": true,
    "cuttingSpeed": 20,
    "handlingTime": 5,
    "loadingTime": 60
  }
}
```

Response (truncated — `cuts` lists every piece with its position on the plate):

```json
{
  "totalPlates": 5,
  "efficiency": 77.31,
  "totalCuts": 42,
  "totalWaste": 6575136.0,
  "estimatedTime": "12m",
  "plates": [
    {
      "plateNumber": 1,
      "totalArea": 5796000.0,
      "usedArea": 4800000.0,
      "quantity": 2,
      "cuts": [
        { "id": "side-0", "pieceId": "side", "x": 0.0, "y": 0.0,
          "length": 600.0, "width": 2000.0, "rotated": false }
      ]
    }
  ]
}
```

Note `totalPlates: 5` against four entries in `plates`: the first layout is used twice, so it is
returned once with `quantity: 2` rather than duplicated. 42 pieces are placed across 5 plates at
77.31% material efficiency.

All dimensions are in millimetres; areas in mm².
Interactive API docs are generated by FastAPI at `http://localhost:8000/docs`.

## Running locally

Requires Python 3.10+ and Node 18+.

**Backend** — from `backend/`:

```bash
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS / Linux
pip install -r requirements.txt
python -m app.main
```

The API starts on `http://localhost:8000`.

**Frontend** — from `frontend/`:

```bash
npm install
npm run dev
```

The UI starts on `http://localhost:5173` and expects the API on port 8000
(configured in `src/api/client.js`).

## Possible extensions

- Persist jobs and layouts to a database instead of keeping them in memory
- Export the layout as a cut list / PDF for the shop floor
- Support plates with defects or pre-existing offcuts as packing input
- Move the API base URL out of the client into an environment variable
